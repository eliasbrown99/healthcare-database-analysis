# Clinical context for the worked examples

The examples demonstrate database use through recognizable workflows. Their dates, people, outcomes, scores, and event frequencies are authored, not clinical evidence. They illustrate review questions and do not establish treatment effectiveness, physician performance, or causal relationships.

## Important boundaries of interpretation

- MedicationOrder contains a selected subset of records. It does not include a complete perioperative, anesthetic, antimicrobial, thromboprophylaxis, or administration record. Absence from this table is not proof a treatment was omitted clinically. An order is not proof a dose was administered.
- StandardDosage is retained as the original catalog's reference text. It is not a universal safe dose, and the source value `Inhaler` is not a complete dose specification. Actual worked orders record their own dose and frequency. Clinical dosing decisions are not generated by this database.
- Infection episodes have named categories, organisms, and dated narratives. Hospital-acquired status is a fictional adjudicated attribute, not a calculated NHSN result. An unresolved date means resolution is not documented; it does not prove active infection.
- FallsRisk and ADLScore use the original project's 1–10 range. Higher falls risk means more risk; higher ADL means more independence. These are fictional care-planning snapshots, not validated clinical instruments or time-series assessments.
- The case set intentionally contains return visits and complications to exercise queries. Its rates cannot be compared with hospital benchmarks. Planned admissions, same-day returns, and complete 30-day follow-up are explicit so a reviewer can inspect the metric definition.
- Physician is limited to physicians in this prototype. Nurse practitioners, physician assistants, therapists, pharmacists, and nursing staff may appear in narratives but are not modeled as physician identities. A broader workforce model would use a provider entity with appropriate professional types.
- The current model stores one organism description per infection episode and one discharge-time care-planning snapshot per hospitalization. Polymicrobial cultures, serial assessments, laboratory results, and authenticated comprehensive audit trails would require additional entities for an operational system.
